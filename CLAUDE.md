# Catapulto FPS

Кооперативный крафт-шутер в духе Volcanoids. Unity **6000.3.20f1**, URP 17.3, Input System (без legacy `Input`).
Сцена: `Assets/Scenes/SampleScene.unity`. Свой код: `Assets/Scripts/<Domain>/`, editor-генераторы: `Assets/Editor/`.
Сторонние паки (`EffectCore`, `Hovl Studio`, `TextMesh Pro`, `TutorialInfo`) не трогать.

Источник правды по геймдизайну и строительству замка: `Docs/GDD_short.md`. Читать перед задачами по замку, магу, карте, луту.

## Общение
- С пользователем на **русском**, коротко и по делу; подробнее только по запросу.
- Идентификаторы, код, коммиты на **английском**. Комментарии в коде на **русском**.

## Игровой контекст
Кор-луп: телепорт на точку → отбиться → разнести вражеский замок → лут → апгрейд своего замка → хронум магу → следующий телепорт.
- Вражеские замки стреляют с башен и спавнят войска.
- Игрок строит и защищает свой замок под осадой.
- Свой замок телепортирует маг между платформами карты.

**Текущий фокус:** каркасные секции. Спавн игрока и врага через `CarcassBuilder`: уникальные колонны + общая стена (2 модуля на сторону). Меню B: Section, Wall, Window, Door. Створка двери открывается на E.

**Запарковано (не удалять, не развивать без запроса):** `SquareCastleBuilder`, редактор раскладки F9 8×8 в `Assets/Scripts/Castle/Layout/`. Как вернуть: `C:\Feeds\Rules\catapulto-castle-sections-restore.md`.

## Как работать
- Менять только то, что нужно задаче. Без попутных рефакторингов.
- Если правка затрагивает **больше одного файла**, сначала коротко показать план и дождаться ок (если план уже одобрен, не спрашивать).
- Небольшие вертикальные срезы вместо больших переписываний.
- **Git в проекте нет.** Перед массовыми правками сцен/префабов предупредить пользователя, что отката не будет.

## Сцены и префабы
- Проводку сцены/префабов (`.unity`, `.prefab`, YAML) делаю сам. Не оставлять «назначь в инспекторе» по умолчанию.
- Предпочитать сетапы без хрупких inspector-only ссылок (например, биндинги ввода в коде), но обязательные ссылки (SO-конфиги, трансформы, компоненты) прописывать.
- YAML-диффы минимальные и осознанные; правильные `fileID`/`guid` из `.meta`.
- После правки сцены/префаба кратко перечислить, что подключено, чтобы пользователь проверил в редакторе.
- Я не вижу Play Mode. Если что-то сломалось в рантайме, прошу текст из Console и чиню сам, не прошу перетаскивать ссылки.

## Принципы
Это MVP, но код пишется так, будто его завтра расширяет другой разработчик.
Приоритеты: **ясность → корректность → расширяемость** (швы для роста, а не фреймворки под воображаемые фичи).
- KISS, YAGNI. DRY только когда у дубля есть общий смысл. Один класс = одна причина меняться. Композиция вместо наследования.
- Паттерн (события, стейт-машина, новый SO-тип) вводить, только если есть 2+ реальных места использования или он снимает боль **сейчас**.
- Имена про «что» и «зачем»: `WeaponFireController`, не `Mgr`/`Helper`/`Util`. Булевы как вопрос: `isReady`, `canFire`.
- Комментарии объясняют **почему**: неочевидные инварианты, грабли жизненного цикла Unity. Без пересказа кода.
- Анти-паттерны: god-классы, побочные эффекты в геттерах, магические числа, преждевременная оптимизация.
- Перед завершением: нет мёртвого кода, неиспользуемых using и закомментированных блоков; ошибки не глотаются молча.

## Билд Windows
- Один плеер в `Builds/Windows/CatapultoFPS.exe`. Без датированных папок, `Build2`, `Windows_old`.
- Собирать через `Catapulto/Build Windows x64` (`BuildWindowsPlayer.Build`, сам удаляет старую папку).
- Batchmode (редактор должен быть закрыт): `Unity.exe -batchmode -quit -projectPath . -executeMethod BuildWindowsPlayer.Build -logFile Builds/build.log`.

Детальные правила по C#/Unity подгружаются из `.claude/rules/` при работе с `.cs` и конфигами.
