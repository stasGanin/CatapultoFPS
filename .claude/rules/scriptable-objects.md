# ScriptableObject-конфиги

Все геймдизайн-тюнинги живут в ScriptableObject. Пользователь балансит через ассеты, а не через код.

## Что в SO
- Бой: урон, RPM, разброс, отдача, перезарядка, патроны.
- Игрок: скорость, спринт, прыжок, ускорение. Камера: чувствительность, FOV.
- Враги: hp, скорость, дальность, кулдауны.
- Флаги фич и общие дефолты, которые дизайнер может крутить.

## Что на MonoBehaviour
- Ссылки на сцену (CharacterController, камера, дуло), рантайм-состояние (текущие патроны, таймеры), ссылка на конфиг.
- Константы, которые никогда не балансятся, — `const` / `static readonly`.

## Конвенции
- Тип оканчивается на `Config` (или `Settings` для проектных): `WeaponConfig`, `PlayerMotorConfig`.
- Один SO-тип = одна забота; варианты = новые ассеты того же типа (Pistol vs Rifle), не подклассы.
- Поля с понятными именами, `[Min(0)]` / `[Range]` где уместно.
- Где лежат ассеты:
  - `Assets/Data/<Domain>/` — конфиги, назначаемые ссылкой в инспекторе.
  - `Assets/Resources/<Domain>/` — только то, что грузится в рантайме через `Resources.Load` (каталоги, определения).
- Дефолтный ассет создаю сам и назначаю на префаб/сцену; null-ссылок на конфиг не оставлять.
- Один тюнинг не дублировать одновременно в SO и в локальном serialized float.

```csharp
[SerializeField] WeaponConfig _config;

void Fire() {
    // значения баланса только из конфига
    var damage = _config.Damage;
}
```
